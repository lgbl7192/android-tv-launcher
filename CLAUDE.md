# android-tv-launcher

Debloat scripts + a custom Apple TV-style home screen for Android TV / Google TV. No root; everything over ADB on the local network. README.md has the user-facing steps; this file is for coding agents.

## Layout
- `debloat/debloat.sh <tv-ip> [list]` hides packages with `pm uninstall -k --user 0` (reversible). `restore.sh <tv-ip> [pkg]` uses `cmd package install-existing`; with no package it restores the whole list and re-enables `com.google.android.tvlauncher`. Lists: one package per line, `#` comments. `adb shell -n` is required inside the `while read` loops, or adb swallows the rest of the list from stdin.
- `launcher/`: Kotlin + Jetpack Compose for TV (`androidx.tv:tv-material`), `androidx.palette`. AGP 8.10 / Gradle 8.11.1 / Kotlin 2.0.21, JDK 17+, minSdk 28. No other dependencies (HTTP via HttpURLConnection, JSON via org.json).
  - `Apps.kt`: LEANBACK apps, banners, glow colour; favourites in SharedPreferences (`launcher`/`favourites`, seeded from `DEFAULT_FAVOURITES`); recents via UsageStatsManager (screensaver excluded).
  - `HomeScreen.kt`: pinned header (`TopBar` overlay; the Column starts with a `barHeight` spacer, and the vertical `minimalScroll` gets `topInset = barHeight` and the page `ScrollState`, so focusing anything on the first screen (the dock) scrolls back to the top and hides the bar, while the LazyRows get the plain spec re-provided). Once scrolled the bar fades in, drawing the wallpaper itself (`drawWallpaper()`, or the background on Plain) under a flat tint to hide the page behind it. Page: header, an empty title-height slot that shows the move hint (`MoveHint`), favourites in a translucent `Dock` at the bottom of the first screen (six across, tile size derived from the dock width; its `minimalScroll` margin equals the padding so it scrolls one whole slot and never shows a partial tile; move mode scrolls the moved tile into view), then below the fold Sports (212x84 score cards) and Recent (200x112); every tile shares `FocusTile`, long-press menu (Move, add/remove favourite, App info). Header pills: Inputs (only with inputs connected), All apps, Home screen (photo icon), Picture/Sound (only when the screen exists), Settings; the first three open panels. With no favourites, first focus goes to All apps. Move mode: left/right, OK or Back finishes; the finishing key-up is swallowed or it launches the app. `OLED_CARE` gates idle/night dimming (22:00-06:00) and pixel shift. Keep scroll, focus, glow and the clock out of the root composition: read them in draw/layout lambdas or small child composables (`Ambient`, `Header`), and use `derivedStateOf` for flags (`light`, `photoUp`).
  - `Wallpaper.kt`: Commons featured pictures per `WallpaperCategory` (one `categorymembers` + `imageinfo` call per category, paged), kept if 1.3-2.0 aspect and >= 1920 px wide and not in `EXCLUDED`. Lists cached weekly (`LIST_VERSION` forces a refetch), current and next photo on disk as 1920 px thumbnails, or 3840 px for photos wider than 1.6:1 (a 1920 one wouldn't cover 1080p plus the parallax strip; Commons serves nothing in between) in `filesDir/wallpaper/`; shuffle bag, no repeats until the pool runs out. `updateWallpaper()` is one blocking step returning `delayMs` (0 = again now, 15000 = retry, else until due); HomeScreen runs it in `repeatOnLifecycle(STARTED)` keyed on `HomePrefs`, skipping Plain, and Next photo sends to a conflated channel that cuts the wait. `loadWallpaperImage()` decodes centre-cropped to the screen plus `ParallaxRange` below it, cuts the scrims out of its alpha (`cutScrims()`), then `prepareToDraw()`. `WallpaperState` crossfades over 1.2s (the first photo after start appears at once). `Wallpaper()` draws the theme's scrim colour and the photo over it in one layer (one flat fill instead of three full-screen gradients each frame); scrolling only moves it (parallax translation) and fades a separate scrim layer (`ModulateAlpha`), so it never re-records. `drawWallpaper()` draws the same layers clipped to the pinned bar. Commons asks for a descriptive User-Agent (`Http.kt`). No credit is shown; `Photo` still keeps name, artist and licence.
  - `HomePrefs.kt`: Appearance (Auto/Light/Dark), Wallpaper (Photos/Plain colour), categories (at least one stays on), change interval; in the `launcher` SharedPreferences.
  - `Sun.kt`: NOAA sunrise/sunset from `lastLocation()`, computed locally; 07:00-19:00 without a location. `isLight()` drives `LauncherTheme(light)`, rechecked on the minute tick.
  - `Theme.kt`: `LauncherColors` light and dark sets via `LocalColors`, animated over 1s on a switch. Gradients fade to the colour at zero alpha, never `Color.Transparent` (unpremultiplied interpolation through black turns a white scrim grey).
  - `Panels.kt`: `ScrimDialog` (full-screen Dialog over the live Home window, dimmed with the theme's scrim at 88%, enough that the header behind doesn't clash with panel titles; the platform dim is turned off so it's light by day), All apps (5-column grid of 150x84 tiles, long-press menu), Inputs, Home screen settings.
  - `Sports.kt`: ESPN site API scoreboards (no key) for `sports.leagues` + `sports.teams` (`league:ABBR`) → BuildConfig. Window: live, starting within 18h, or started within 10h and final; college only ranked games plus yours; your idle teams get their next game from `/teams/{id}/schedule` (cached 6h; ids looked up from the league team list, since `/teams/{abbr}` fails for soccer/college). Max 12; card opens the first installed app for the game's network (`NETWORK_APPS`), else ESPN. Logos at 64px via ESPN's combiner, cached in memory. Polled from HomeScreen inside `repeatOnLifecycle(STARTED)`: 60s while live, 15 min otherwise.
 - `Media.kt`: `MediaListener` is an empty `NotificationListenerService`; being an enabled listener (granted over adb) is what allows `MediaSessionManager.getActiveSessions`. `rememberNowPlaying()` watches sessions while Home is STARTED and picks the one playing, or the one already shown while it's paused, so the card's play button keeps working. `NowPlayingCard` (art, title, artist, progress ticking on its own, prev/play-pause/next pills) pops up above the dock via `NowPlayingSlot`, a child composable so playback changes don't recompose the page. No grant = no card.
  - `Inputs.kt`: HDMI inputs as `TvApp(isInput = true)`; CEC child inputs give the device name; hidden unless connected.
  - `Weather.kt`: `lastLocation()` (shared with `Sun.kt`) + Open-Meteo (no key). `Http.kt`: shared GET helpers with a descriptive User-Agent. `Fonts.kt`: Inter variable font, `UiText` (opsz 14, default) / `UiDisplay` (opsz 32, for 20sp+).
  - `MainActivity.kt`: HOME activity; reloads on package changes; Home closes any panel or menu and re-focuses the first favourite; Back swallowed. `launchFresh` kills the target's background process first (Live TV apps and Stremio ignore new inputs/links while running).

## Design rules (tvOS-like)
Favourites sit in a translucent dock; the other rows have no container and bleed to the screen edge (`EdgePadding` as content padding). Focus = scale + app-colour glow + light rim + glare, never a thick border. Sentence-case type, weight not letter-spacing. No glass: surfaces are flat translucent fills with no blur, highlight or edge, so the wallpaper shows through sharp. Pills, the dock and the now-playing card use `smokeFill` (dark in both themes, content in `onSmoke`); score cards and bannerless tiles use `surfaceFill`; the long-press menu is nearly solid (`menuFill`) so nothing behind shows through its items. Focused pills = solid white. The wallpaper fills the screen, and dims and parallaxes as the page scrolls; the app glow shows only on the plain background. Light by day, dark at night; every colour comes from `LocalColors`.

## Build & deploy
```
cd launcher && cp local.properties.example local.properties   # sdk.dir + optional sports.*
./gradlew assembleRelease
S=<tv-ip>:5555
adb -s $S install -r app/build/outputs/apk/release/app-release.apk
adb -s $S shell pm grant me.prince.launcher android.permission.ACCESS_COARSE_LOCATION
adb -s $S shell appops set me.prince.launcher GET_USAGE_STATS allow
adb -s $S shell cmd notification allow_listener me.prince.launcher/me.prince.launcher.MediaListener
adb -s $S shell cmd package compile -m speed -f me.prince.launcher
adb -s $S shell cmd package set-home-activity me.prince.launcher/.MainActivity
```
Always ship release (R8); debug Compose is too slow on TV hardware.

## Rules when working on a user's TV
- Connecting: classic network ADB is `<ip>:5555`; TVs with "Wireless debugging" (Google TV, Android 11+) need `adb pair <ip>:<pairing-port>` with the on-screen code, then `adb connect <ip>:<port>`. The scripts accept `<ip>` or `<ip>:<port>`.
- Ask before removing any package. Never remove Live TV, `com.mediatek.*` / other chip services, the remote's Bluetooth service, `com.android.tv.settings`, Play Services, the keyboard or setup wizards.
- Disable (never uninstall) the stock launcher, and only after the custom launcher is installed and verified, otherwise Home shows a black screen. Fallback: `pm enable com.google.android.tvlauncher`. Warn the user that this can break hands-free "Ok Google" (README → Gotchas).
- Test by screenshotting: `adb shell screencap -p /sdcard/s.png` then `adb pull` (some TVs print vendor log lines into `exec-out` output, corrupting the PNG). Protected video and HDMI inputs capture as black. Between 22:00 and 06:00 the OLED night dim greys every screenshot.
- Before sending key events (`input keyevent`), check `dumpsys activity activities | grep mResumedActivity`: if a video app or TV input is in front, someone may be watching.

## Gotchas already handled in code
- Compose for TV pins the focused item 30% from the edge, scrolling the header off-screen; `minimalScroll()` (a custom BringIntoViewSpec) only scrolls when an item would leave the screen.
- On cold start the first tile isn't attached for a few frames; focus is requested with a short retry loop.
- The first TLS handshake after start sometimes fails (seen with AdGuard's HTTPS filtering); the wallpaper, sports and weather loops retry every 15s until they get data, and the last photo shows from disk meanwhile.
- Dialogs are separate windows: key presses in a panel don't reach HomeScreen's `onPreviewKeyEvent`.
